# moonbit-csv 需求分析

## 1. 项目背景

MoonBit 生态仍在快速建设阶段，很多常见基础库还不够完善。CSV 作为最常见的数据交换格式之一，在以下场景中频繁出现：

- 配置导入导出
- 数据清洗与转换
- 示例数据读写
- 简单报表处理
- 与其他语言系统进行文本级互操作

因此，一个可用、可测、接口清晰的 CSV 库具备明确生态价值。

## 2. 项目目标

本项目要解决的是“MoonBit 中基础 CSV 读写能力缺失”的问题，而不是构建完整的数据分析平台。

目标如下：

- 提供基础、稳定、易理解的 CSV 解析能力
- 提供配套写出能力，保证读写行为可预期
- 为 MoonBit 生态提供一个可直接复用的基础包
- 在比赛周期内完成高完成度交付

## 3. 用户画像

主要用户包括：

- MoonBit 初学者：需要简单可用的 CSV 示例库
- 工具开发者：需要导入导出结构化文本数据
- 教学和示例项目作者：需要轻量依赖和清晰 API
- 生态贡献者：需要可扩展、可继续维护的基础模块

## 4. 核心使用场景

### 4.1 解析 CSV 文本

输入一段 CSV 字符串，得到按行组织的二维字符串数组。

### 4.2 处理带表头的数据

第一行作为表头，后续行为记录，便于业务层按列名访问。

### 4.3 写出 CSV 文本

将二维字符串数组重新编码为合法 CSV，并自动处理逗号、引号和换行。

### 4.4 错误输入识别

当输入包含未闭合引号、非法转义或不完整记录时，返回明确错误。

## 5. 功能需求

### 5.1 必须实现

- 从字符串解析 CSV
- 输出按行组织的字段列表
- 支持空字段
- 支持带引号字段
- 支持字段内逗号
- 支持字段内双引号转义
- 支持 `\\n` 和 `\\r\\n` 换行
- 支持将记录编码回 CSV 字符串
- 支持最小可用错误报告
- 提供完整单元测试
- 提供最小示例

### 5.2 建议实现

- 支持表头读取辅助 API
- 支持自定义分隔符
- 支持是否严格校验列数一致
- 支持空输入与尾部空行策略配置

### 5.3 暂不实现

为了控制范围，以下内容第一版不做或仅预留扩展位：

- 真正的流式大文件 IO
- 自动类型推断
- 与数据库或 DataFrame 直接集成
- 复杂 Excel 兼容策略
- 容错式“猜测修复”解析

## 6. 非功能需求

### 6.1 易用性

- API 命名清晰
- 默认行为符合直觉
- 新手无需理解内部状态机即可上手

### 6.2 稳定性

- 对合法输入结果稳定
- 对非法输入行为可预测
- 重要边界有测试覆盖

### 6.3 可维护性

- 模块职责清楚
- 解析器和编码器解耦
- 错误类型明确
- 文档与实现保持一致

### 6.4 可测试性

- 解析结果适合直接断言
- 边界条件可构造
- 读写可形成往返测试

## 7. 输入输出分析

### 输入

- 原始 CSV 字符串
- 可选解析配置
- 可选编码配置

### 输出

- 成功时返回结构化记录
- 失败时返回错误信息

## 8. 边界条件

需要优先考虑的边界包括：

- 空字符串
- 单行单列
- 多行多列
- 行尾空列
- 空行
- 带引号且内部有逗号
- 带引号且内部有换行
- `""` 转义双引号
- 未闭合引号
- 结尾为 `\\r`

## 9. 验收视角

从比赛验收角度，这个项目应满足：

- 功能边界清晰
- 可运行示例存在
- 代码结构清晰
- README 可复现
- 测试覆盖核心路径
- 适合发布到 `mooncakes.io`

## 10. 结论

`moonbit-csv` 是一个实现成本可控、生态价值明确、测试友好、展示直观的选题。它非常适合在短周期内做成一个完整的 MoonBit 开源基础库，并满足比赛对“真实可用、文档完整、测试可运行”的要求。
